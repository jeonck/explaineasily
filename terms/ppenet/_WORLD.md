# PPE·네트워크 세계관: 우체국 택배 배송망

## 무대
- 배송망 = 통신망. 봉투 = 패킷. 집배원이 봉투를 들고 우체국(라우터)들을 거쳐 분류소(스위치)에서 나뉘어 목적지로 간다.
- 등기 봉투 = TCP(확인받고 보냄), 일반 봉투 = UDP(확인 없이 빠르게). 배송 경로 지도 = 라우팅 테이블. 톨게이트 = 스위칭/회선·패킷 교환.
- 배경: 낮 `sky()` = 평상시 배송, `bad-soft` = 배송 사고/정체 패널, `good-soft` = 개선·비교 패널.
- 긴장: 등기(TCP)는 확실하지만 느리고, 일반우편(UDP)은 빠르지만 중간에 잃어버릴 수 있다 — **확실함 vs 속도**가 이 세계의 핵심 선택.

## 등장인물 (헬퍼는 `terms/ppenet/_world.py`)
| 인물 | 그림 | 실제 |
|---|---|---|
| 우체국장 | `person(..., **CLERK)` 보라 | 라우터 |
| 집배원 | `person(..., **CARRIER)` 파란 모자 | 패킷 운반 |
| 분류소 직원 | `person(..., **SORTER)` 초록 | 스위치 |
| 보내는 사람 | `person(..., **SENDER)` | 송신 측 |
| 받는 사람 | `person(..., **RECEIVER)` 주황 | 수신 측 |

## 소품 = 개념
| 소품 | 헬퍼 | 실제 |
|---|---|---|
| 봉투(registered=등기) | `envelope()` | 패킷 (TCP/UDP) |
| 우체국 건물 | `postoffice()` | 라우터 / 게이트웨이 |
| 배송 경로 지도 | `routemap()` | 라우팅 테이블 / 안내판 |
| 톨게이트 | `tollgate()` | 스위칭 / 회선·패킷 교환 |
| 배달 트럭 | `truck()` | 5G / 고속 전송 |

## 깨지는 곳
- 등기(TCP)도 만능은 아니다 — 확인을 주고받는 절차 자체가 느려지는 원인이 된다(혼잡 제어가 필요한 이유).
- 주소(IP)가 틀리면 아무리 빨라도 엉뚱한 곳에 도착한다 — 그래서 주소록(DNS)과 경로 관리가 함께 필요하다.

## 다른 세계와의 다리
- `security`(성) 세계의 `vpn`·`dns` 는 이미 다뤘다 — 이 세계에서는 네트워크 "동작 원리" 자체(프로토콜·라우팅·교환방식)에 집중하고 해당 용어는 새로 쓰지 않고 링크한다.
