# PPE·SW공학 세계관: 책 만드는 출판사

## 무대
- 출판사 = 소프트웨어 개발 조직. 작가가 원고(요구사항)를 쓰고, 편집장이 기획·일정을 관리하고, 교정자가 오탈자(결함)를 잡고, 인쇄소가 책(배포본)을 찍어 독자(사용자)에게 전한다.
- 원고 = 요구사항/설계. 교정지 = 테스트케이스. 인쇄판 = 배포 산출물. 서가 = 형상관리(버전·이력). 스타일가이드 = 디자인패턴/아키텍처 원칙. 매수 계산 자 = 기능점수(FP)/규모산정.
- 배경: 낮 `sky()` = 평상시 작업, `bad-soft` = 오류·지연 패널, `good-soft` = 개선·합의 패널.
- 긴장: 빨리 내고 싶은데, 서두르면 독자가 오탈자(결함)를 발견한다 — **속도 vs 꼼꼼함**이 이 세계의 핵심 긴장. "완벽한 초고"는 없고, 여러 번 고쳐 쓰는 과정(개발방법론·품질관리) 자체가 공학이다.

## 등장인물 (헬퍼는 `terms/ppeswe/_world.py`)
| 인물 | 그림 | 실제 |
|---|---|---|
| 편집장 | `person(..., **EDITOR)` 보라 | PM / 기획자 |
| 작가 | `person(..., **WRITER)` 파란 모자 | 개발자 |
| 교정자 | `person(..., **PROOFER)` 초록 | 테스터 / QA |
| 인쇄 감독 | `person(..., **PRINTER)` 주황 | 정보시스템 감리 |
| 독자 | `person(..., **READER)` 모자 없음 | 최종 사용자 |

## 소품 = 개념
| 소품 | 헬퍼 | 실제 |
|---|---|---|
| 원고(빨간 표시=결함) | `manuscript()` | 요구사항 명세 / 결함 |
| 인쇄판 | `printplate()` | 배포 산출물 |
| 보관 서가 | `bookshelf()` | 형상관리(SCM) / 버전 |
| 스타일가이드/안내판 | `styleguide()` | 디자인패턴 / 아키텍처 원칙 / 체크리스트 |
| 승인 도장 | `inkstamp()` | 품질 승인 / 배포 승인 |
| 매수 계산 자 | `ruler()` | 기능점수(FP) / 규모산정 |

## 깨지는 곳
- "오탈자 0건"은 현실에 없다 — 좋은 출판 공정은 오탈자를 없애는 게 아니라 **빨리, 싸게 찾아내는 구조**를 만드는 것(테스트/품질관리의 핵심).
- 편집 규칙(방법론)은 책마다 다르게 적용해야 한다 — 모든 책에 같은 규칙을 강제하면 오히려 늦어진다(방법론 테일러링).

## 다른 세계와의 다리
- `llmsec`(주방)·`sre`(놀이공원) 는 "다 만든 뒤 운영"에 집중하고, 이 세계는 "만드는 과정 자체"(방법론·품질·형상관리)에 집중한다 — 배포 이후 안정성은 `sre`로 링크.
