In one breath

Technical debt is the 'debt' of work postponed to move fast now. Left unpaid, the cost to fix it keeps growing like interest.

Technical debt is a metaphor for the future cost incurred when a faster, lower-quality approach is chosen over a better design now. It splits into deliberate debt (knowingly taken on) and inadvertent debt (accumulated without realizing it); left unpaid, the cost to fix it compounds like interest. The goal isn't zero debt — it's tracking it in a backlog and repaying it deliberately.

When grown-ups say it

Technical Debt
A debt that must be repaid later. Left unpaid, it grows like interest.
Deliberate Debt
Debt knowingly taken on, for speed. Not bad in itself — recording it is what matters.
Inadvertent Debt
Debt that piles up from an unnoticed mistake. Often discovered only much later.
Refactoring
The classic way to repay this debt. Keeping the plot the same while reworking the structure. → same plot, retouched sentences
Code Smell
The whiff of sentences gone tangled. A sign the debt is piling up.
WBS
Why schedule pressure makes debt easy to accumulate. Too tight a schedule, and this debt piles up. → laying out the book as a tree
IS Audit/PMO
The outside checker watching whether debt has piled up too far. Watches debt across many projects at once. → the last checker before publication
Unit Test
The proofing that checks the plot held while the debt is repaid. Without tests, repaying debt safely is hard.
