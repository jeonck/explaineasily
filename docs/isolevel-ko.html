트랜잭션 격리 수준이 뭐예요?

격리 수준과 이상현상을, 같은 상자를 동시에 만지는 포장 담당과 배송 기사 이야기로 풀어봤어요.

포장 담당과 배송 기사가 같은 상자를 동시에 만져요.동시에 손대면 서로 다른 숫자를 봐요.

규칙 없이 두면 세 가지 사고가 나요.더티 리드·반복 불가 읽기·유령 읽기예요.

격리 수준 = 동시에 손댈 때 얼마나 엄격히 막을지 정하는 규칙이에요.엄격할수록 안전하지만, 느려질 수 있어요.

더티 리드 막기확정 전엔 못 봐요
같은 값 보장하기다시 읽어도 안 변해요
유령 읽기 막기새로 끼어든 행도 막아요
차례로 처리하기가장 엄격한 Serializable

격리 수준은 네 단계로 나뉘어요.Serializable이 가장 엄격해요.

Serializable은 가장 안전하지만, 뒷사람이 오래 기다려요.그래서 상황에 맞는 수준을 골라야 해요.

한 줄로

격리 수준 = 여러 사람이 동시에 같은 데이터를 손댈 때, 서로의 작업이 얼마나 보이고 가려질지 정하는 규칙.

트랜잭션 격리 수준은 Read Uncommitted·Read Committed·Repeatable Read·Serializable 네 단계가 있고, 낮을수록 더티 리드·반복 불가 읽기·팬텀 리드 같은 이상현상이 더 많이 허용돼요. 격리가 강할수록 일관성은 높아지지만 동시 처리량(성능)은 떨어져요.

어른들은 이렇게 불러요

더티 리드
Dirty Read
아직 확정 안 된 값을 보는 것. Read Uncommitted에서만 생겨요.
반복 불가 읽기
Non-repeatable Read
같은 걸 다시 읽었더니 값이 바뀜. Repeatable Read부터 막혀요.
유령 읽기(팬텀 리드)
Phantom Read
없던 행이 다시 조회하니 생겨남. Serializable에서 완전히 막혀요.
Serializable
Serializable
차례로 하나씩 처리한 것처럼 만드는 수준. 가장 엄격하고 가장 느려요.
ACID
ACID
전표가 지키는 네 가지 약속. 격리(I)는 그중 하나예요. → 전표가 지키는 네 약속
병행제어
Concurrency Control
격리 수준을 실제로 지켜내는 방법. 락이나 MVCC로 구현해요. → 동시에 안 부딪히는 규칙
CAP 정리
CAP Theorem
놀이공원 세계의 트레이드오프 이야기. 분산 환경에서 일관성 자체의 한계를 다뤄요. → CAP 정리
최종 일관성
Eventual Consistency
당장은 달라도 결국 같아지는 것. 격리 수준과는 또 다른 분산 환경의 타협이에요. → 최종 일관성
