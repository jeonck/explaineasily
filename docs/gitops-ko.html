GitOps가 뭐예요?

GitOps를 설계도 보관함에 새 설계도를 넣으면 자동으로 공사가 시작되는 이야기로 풀어봤어요.

설계도는 고쳤는데, 실제 공사는 깜빡 잊기도 해요.한참 뒤에야 반영돼요.

설계도 수정과 실제 공사가 따로 놀면, 사람이 깜빡해요.두 단계로 나뉘어 있으면 꼭 하나를 잊어버려요.

보관함에 새 설계도를 넣으면, 공사팀이 자동으로 알아채고 바로 지어요.보관함이 늘 지금의 정답이에요.

설계도를 보관함에 넣으면 끝그다음은 안 해도 돼요
공사는 자동으로 따라와요알아서 알아채요
보관함이 항상 정답이에요지금 어때야 하는지요
다르면 자동으로 다시 맞춰요실제를 보관함에 맞춰요

넣는 순간 → 자동 감지 → 공사 → 완료.사람이 중간에 끼어들 일이 없어요.

보관함에 잘못된 설계도를 넣으면, 그대로 자동 반영돼요.넣기 전에 검토가 꼭 필요해요.

한 줄로

GitOps = 설계도 보관함을 지금의 유일한 정답으로 삼아서, 보관함에 새 설계도가 들어가면 공사가 자동으로 따라오게 하는 일.

Git 저장소를 유일한 정답(단일 진실 공급원)으로 삼아 인프라를 운영하는 방식이에요. 저장소가 바뀌면 자동화 도구가 그 차이를 감지해 실제 환경을 끌어다 맞춰요(풀 기반 배포). 실제가 저장소와 달라지면 자동으로 다시 동기화하고, 되돌릴 땐 저장소를 이전 커밋으로 되돌리면 돼요.

어른들은 이렇게 불러요

GitOps
GitOps
설계도 보관함이 바뀌면 공사가 자동으로 따라오는 방식. 코드형 인프라의 다음 단계예요.
저장소를 단일 진실 공급원으로
Repo as single source of truth
보관함이 항상 정답. 실제가 거기에 맞춰져야 해요.
자동 동기화
Auto-sync
실제와 보관함이 다르면 자동으로 맞추는 일. 사람이 따로 맞출 필요가 없어요.
풀 기반 배포
Pull-based deployment
공사팀이 알아서 보관함에서 가져가는 방식. 누가 밀어 넣는 게 아니라 끌어가요.
코드형 인프라
Infrastructure as Code
설계도를 종이 한 장(코드)에 적는 일. GitOps가 다루는 그 설계도예요. → 설계도 한 장으로 공원 통째로 짓기
리뷰·승인 절차
Review and approval
보관함에 넣기 전 검토하는 일. 여기서 걸러야 실수가 자동으로 퍼지지 않아요.
롤백
Rollback
보관함을 이전 설계도로 되돌리는 일. 되돌리면 실제도 자동으로 따라와요.
CI/CD
CI/CD
설계도를 검토하고 보관함에 올리기까지의 앞단계. GitOps는 그 뒤, 보관함부터 공사까지를 맡아요.
