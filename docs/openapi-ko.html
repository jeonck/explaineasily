개방형 API(Open API)가 뭐예요?

개방형 API를, 전화로 매번 따로 부탁하는 대신 표준 신청서식 하나로 누구나 자료를 빌려볼 수 있게 연 열람실 이야기로 풀어봤어요.

남이 우리 자료를 보려면 매번 전화해서 따로 부탁해야 해요.사람마다 요청 방식이 달라서 매번 새로 설명해야 해요.

양식이 저마다 달라 확인하는 데 오래 걸려요.편집장이 하나하나 다시 확인해야 해서 느려요.

개방형 API는 표준 신청서식을 공개한 열람실이에요.이 서식대로만 쓰면, 누구나 바로 자료를 빌려볼 수 있어요.

신청서식 표준화요청 방법을 미리 정해 공개해요
열람 창구 열기서식대로 오면 누구나 받아줘요
이용키 발급누가 빌려 가는지는 확인해요
이용 범위 정하기어디까지 빌릴 수 있는지 정해둬요

이 명세서 하나로 누구나 신청할 수 있어요.무엇을 어떻게 요청하고, 무엇을 돌려받는지 미리 다 적혀 있어요.

여는 것과 줄 세우는 건 다른 일이에요.개방형 API는 무엇을 공개할지의 정책이고, 몰려드는 요청을 실제로 다루는 건 → 정문 안내소 쪽 몫이에요.

한 줄로

개방형 API(Open API) = 전화로 매번 따로 부탁하는 대신, 표준 신청서식을 미리 공개해서 누구나 같은 방식으로 자료를 빌려볼 수 있게 하는 것.

개방형 API는 공공기관이나 기업이 보유한 데이터·기능을 표준화된 명세(요청 형식, 응답 형식, 인증 방식)로 외부에 공개해, 누구나 이 명세대로 요청하면 이용할 수 있게 하는 정책이자 기술 방식이에요. OpenAPI(Swagger) 같은 명세 표준으로 문서화하고, 이용키 발급과 쿼터로 이용 범위를 관리해요. 공공데이터포털의 '오픈API'가 대표적인 예예요.

어른들은 이렇게 불러요

개방형 API
Open API
표준 서식 하나로 연 열람실. 누구나 같은 방식으로 자료를 요청해요.
API 명세(스펙)
API Specification
신청서식 그 자체를 적은 문서. OpenAPI(Swagger) 같은 표준으로 적어요.
이용키(인증키)
API Key
누가 빌려 가는지 확인하는 열쇠. 신청하면 자동으로 발급돼요.
공공데이터포털
Public Data Portal
정부가 연 가장 큰 열람실. 수많은 기관의 개방형 API가 여기 모여 있어요.
데이터 표준화
Data Standardization
응답 모양을 다 같이 맞추는 것. 모양이 다르면 서식이 있어도 쓰기 어려워요.
API 게이트웨이
API Gateway
몰려드는 요청을 실제로 다루는 안내소. 개방형 API는 정책, 게이트웨이는 그 요청을 다루는 인프라예요 → 정문 안내소.
EIF(외부연계파일)
External Interface File
다른 출판사 자료를 참고하는 연결점. 규모를 잴 때 이 연결도 하나로 세어요 → 매수를 재는 자.
이용 쿼터
Usage Quota
한 열쇠로 하루에 빌릴 수 있는 한도. 너무 많이 요청하면 그날은 더 못 빌려요.
