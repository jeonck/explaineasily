제품계열(Product Line) 방법론이 뭐예요?

여러 지역판 가이드북을 하나의 공통 틀에서 빠르게 찍어내는 이야기예요.

지역판마다 가이드북을 처음부터 새로 써요.판이 늘어날수록 반복되는 일도 늘어나요.

겹치는 챕터도 매번 새로 쓰다 보니 설명이 달라져요.매번 새로 쓰면 느리고, 판마다 품질도 들쭉날쭉해져요.

제품계열 = 공통 챕터는 한 번만 만들고, 다른 부분만 바꿔 끼우는 거예요.서가의 핵심 자산에서 각 판으로 빠르게 찍어내요.

핵심 자산 모으기겹치는 챕터부터 한 곳에
가변점 표시하기판마다 달라질 자리만 콕 집어
빠르게 파생하기자산 + 가변점 = 새 판
자산도 버전 관리서가 자체도 계속 고쳐나가요

자산은 둘로 나뉘어요 — 공통 부분과 가변점.공통은 한 번, 다른 건 가변점에서만 갈라져요.

제품계열도 공짜는 아니에요.핵심 자산 설계를 잘못하면 모든 판이 함께 영향받아요.

한 줄로

제품계열(Product Line) 방법론 = 공통된 핵심 자산을 모아두고, 가변점만 바꿔서 여러 제품(판)을 빠르게 파생시키는 개발 방식.

도메인 분석을 통해 제품군의 공통점과 차이점을 미리 식별하고, 공통점은 핵심 자산 저장소에, 차이점은 가변점으로 설계해 둡니다. 새 제품은 핵심 자산을 재사용하고 가변점만 구체화해 만들기 때문에 개발 속도와 일관성이 크게 올라가요.

어른들은 이렇게 불러요

제품계열(SPL)
Software Product Line
공통 틀에서 여러 판을 찍어내는 개발 방식. 도메인 공학이 바탕이에요.
핵심 자산
Core Asset
모든 판이 공유하는 서가. 한 번 만들어 계속 재사용해요.
가변점
Variation Point
판마다 달라지는 자리. 여기만 바뀌면 새 판이 나와요.
도메인 공학
Domain Engineering
제품군 전체의 공통점을 미리 찾는 작업. 핵심 자산을 설계하기 전 단계예요.
재사용
Reuse
서가에서 꺼내 쓰는 것. 제품계열의 핵심 이득이에요.
개발방법론 테일러링
Methodology Tailoring
규칙집에서 필요한 것만 고르기. '맞춤'을 다루는 자매 개념이에요. → 책마다 다른 편집 규칙
결합도/응집도
Coupling/Cohesion
챕터끼리 얼마나 얽혀있나. 핵심 자산이 잘 나뉘었는지 재는 잣대예요. → 챕터가 서로 얼마나 엮여있나
형상관리
Configuration Management
핵심 자산 버전을 지키는 서가 관리. 가변점을 관리하는 바탕이 돼요.
