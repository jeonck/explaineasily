In one breath

An access-control model is a rule for who decides the keys. DAC lets the owner decide, MAC follows a fixed rank-list, RBAC assigns by hat (role).

Discretionary Access Control (DAC) lets the resource owner grant permissions at their own discretion; Mandatory Access Control (MAC) enforces centrally fixed security labels that not even the owner can override; Role-Based Access Control (RBAC) binds permissions to roles and assigns users only a role. Exam questions often compare these three by who decides, how flexible each is, and where each is typically applied.

When grown-ups say it

Discretionary Access Control
The room's owner decides directly. Flexible — but one owner's mistake becomes an incident immediately.
Mandatory Access Control
The king's rank-list — nobody can override it. Its precise read/write rules live in their own page. → Access-control security models (BLP/Biba)
Role-Based Access Control
Keys go to the hat (role), not the person. The most commonly used model. → a key ring for every hat
Attribute-Based Access Control
The gatekeeper's if-sentence. Combines several tags (attributes) into one condition. → the gatekeeper's if-sentence
Security label
The king's rank stamp. A fixed rank attached to both the room and the person, under MAC.
Least privilege
Only the key you actually need. A principle every model should still follow. → only the key you need
Audit
Checking who holds a key, and why. A clear rule is what lets the inspector check it at all. → the inspector from the neighboring kingdom
Hybrid model
A castle running all three together. Real organizations blend DAC, MAC, RBAC and ABAC, each where it fits.
