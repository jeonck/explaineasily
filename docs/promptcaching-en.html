What is prompt caching?

Prompt caching, told as a story about laying out the usual front beans ahead of time and adding only the new ones.

The same rulebook goes on the tray every time — and costs money and time every time.The question is one line, but the rulebook is 30 pages. The parrot reads all 30 before answering — and the bean cost comes every time.

The parrot re-reads every bean on the tray from the start, every time.Even if the front is identical to yesterday, the parrot cannot tell. Every bean on the tray is read fresh, and you pay for each.

Prompt caching lays out the usual front beans ahead of time, then adds only the new ones.The parrot briefly remembers a front part it has already read. For the next guest it skips that part and reads only the new beans — cheaper and faster.

Fixed things go firstrulebook, owner note, samples
Changing things go lastthe guest question at the end
Reorder it and it breaksthe front must match to the letter
It lives only a whileafter some minutes it reads again

With the same front, it is cheap and fast from the second time on.Grey beans cost only a little. The first time costs slightly more to lay them out; from the second time on you win.

Change one character at the front and it starts over. That is why the order of notes matters.Put the date or the guest name at the top of the owner note and it breaks every time. Move what changes to the back.

In one breath

Prompt caching = lay out the usual front beans ahead, then add only the new ones. Fixed things go first, changing things last — if the front differs by one character, it starts over.

Stores the processed result of a prompt prefix for a short time (TTL) and reuses it for later requests that start with the same prefix. On a cache hit, input-token cost drops sharply and latency shrinks. The key is layout: system prompt, long documents and examples first, the user question last.

When grown-ups say it

Prompt caching
Beans laid out ahead. Read the front once, skip it next time. Cheaper and faster.
Cache hit
The front matched exactly. Handled as grey beans. If it does not match, a cache miss — everything again.
Prefix
The front of the tray. How far from the first bean things are identical. Only that part is cached.
TTL (time to live)
It lives only a while. Usually a few minutes. After that it must be laid out again.
System prompt placement
The owner note goes first. The fixed note must sit at the front for the cache to survive. → the trainer note
Context
The tray. The cache remembers the front of the beans on the tray. → the tray
Cost
The bean price. Grey beans are much cheaper. → the bean price
Latency
The wait until an answer. Skipping the front makes the first answer faster. → what answering costs
