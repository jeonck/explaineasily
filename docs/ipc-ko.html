IPC(네트워크 프로세스 간 통신)이 뭐예요?

네트워크 IPC를, 멀리 떨어진 건물 사이에 전용 편지함을 열어 손발을 맞추는 이야기로 풀어봤어요.

서로 다른 건물에서 일하는 두 프로세스가 손발을 맞춰야 해요.소리쳐도 안 들려요 — 건물이 멀리 떨어져 있어요.

아무 봉투나 던지면 잃어버리거나 뒤섞여요.건물 사이 전용 편지함이 없으면 생기는 일이에요.

네트워크 IPC = 건물 사이에 여는 전용 편지함이에요.소켓이나 메시지 큐로, 멀리 있어도 손발을 맞춰요.

소켓실시간 통화 같은 연결
메시지 큐쌓아뒀다 나중에 꺼내요
포트 번호건물 안 창구를 지정해요
TCP/UDP등기냐 일반우편이냐

편지함에도 두 가지 방식이 있어요.실시간 통화처럼 연결해두거나, 쌓아뒀다 나중에 꺼내가요.

같은 건물 안 전달과는 다른 이야기예요.같은 건물 안 부서 간 전달(로컬 IPC)은 또 다른 이야기예요.

한 줄로

네트워크 IPC = 멀리 떨어진 건물(서로 다른 컴퓨터의 프로세스) 사이에 전용 편지함(소켓·메시지 큐)을 열어 주고받는 일.

네트워크를 통한 프로세스 간 통신(IPC)은 서로 다른 호스트에 있는 프로세스가 소켓이나 메시지 큐 같은 수단으로 데이터를 주고받는 방식이에요. 같은 컴퓨터 안 프로세스끼리 쓰는 공유 메모리·파이프 같은 로컬 IPC와 달리, 네트워크 IPC는 TCP/UDP와 포트 번호를 거쳐 원격지와 통신해요.

어른들은 이렇게 불러요

소켓
Socket
실시간으로 연결해두는 전용 편지함. IP와 포트로 상대를 특정해요.
메시지 큐
Message Queue
쌓아뒀다 나중에 꺼내가는 편지함. 보내는 쪽과 받는 쪽이 동시에 있지 않아도 돼요.
포트 번호
Port Number
건물 안 몇 번 창구인지. 같은 주소 안에서 서비스를 구분해요.
TCP/UDP
TCP/UDP
등기 봉투와 일반 봉투. 이 세계의 두 기본 배송 방식이에요.
전송계층
Transport Layer
포트와 등기·일반우편을 다루는 단계. 네트워크 IPC가 기대는 바로 그 계층이에요. → 포트를 나누고 신뢰도를 고르는 단계
Modbus
Modbus
산업 현장에서 쓰는 단순한 쪽지 규칙. 이 전용 편지함 위에서 쓰이는 쪽지 규칙의 한 예예요. → 우체국장이 순서대로 묻는 쪽지 규칙
로컬 IPC(OS 수준)
Local IPC (OS-level)
같은 건물 안 부서끼리 복도로 전달하는 방식. 이건 다른 세계(PPE·시스템SW)에서 다루는, 건물 안 전달 이야기예요.
회선교환·패킷교환
Circuit vs Packet Switching
편지가 실제로 오가는 길의 종류. 전용 편지함 아래 깔린 전송 방식이에요. → 전용 도로냐, 조각내 보내기냐
