오케스트레이션이 뭐예요?

오케스트레이션을 기구마다 몇 대씩 운영할지 정해 주는 공원 운영 본부 이야기로 풀어봤어요.

기구마다 몇 대씩 켤지, 사람이 수첩에 적어가며 정해요.하나 고장 나면 새로 세울지도 사람이 그때그때 결정해요.

기구가 수십 종류, 수백 대면 사람이 다 못 챙겨요.수첩 한 권으로는 규모가 커지면 금방 한계가 와요.

규칙판 하나만 주면, 하나가 죽어도 자동으로 새로 세우고 자리도 배정해요.사람은 규칙만 바꾸면 끝이에요.

죽으면 자동으로 새로 세워요사람이 안 봐도요

1대가 꺼지면, 본부가 바로 빈 자리에 새 1대를 세워요.규칙에 적힌 숫자를 다시 채울 때까지 멈추지 않아요.

본부 자체가 복잡한 시스템이에요.작은 공원엔 오히려 과해요 — 기구 몇 대 안 되면 사람이 더 빨라요.

한 줄로

오케스트레이션 = "이 기구는 항상 몇 대" 규칙만 정해 두면, 하나가 죽어도 자동으로 새로 세우고 자리까지 알아서 배정해 주는 운영 본부.

컨테이너 오케스트레이션(대표적으로 쿠버네티스)을 가리켜요. 선언적 설정으로 '원하는 상태'만 적어 두면, 오케스트레이터가 실제 상태를 그 목표에 계속 맞춰요. 자동 재시작, 스케줄링(배치), 오토스케일링, 롤링 업데이트가 전부 이 위에서 돌아가요.

어른들은 이렇게 불러요

오케스트레이션
Orchestration
운영 본부가 기구를 알아서 관리하는 일. 규칙만 주면 나머지는 본부가 해요.
컨테이너
Container
기구 한 대를 똑같이 포장해 둔 것. 성 세계에서는 짐칸이라고 불러요. → 똑같이 찍어낸 짐칸
선언적 설정
Declarative config
"기구A: 3대" 같은 규칙판. 방법이 아니라 원하는 결과만 적어요.
자동 재시작
Auto-restart
죽은 기구를 알아서 새로 세우는 일. 사람이 호출받을 필요가 줄어들어요.
스케줄링
Scheduling
새 기구가 어느 자리에 설지 정하는 일. 빈자리를 본부가 알아서 골라요.
오토스케일링
Autoscaling
줄이 길어지면 대수를 더 늘리는 일. 규칙판의 숫자 자체가 자동으로 바뀌는 것뿐이에요.
롤링 업데이트
Rolling update
기구를 하나씩 순서대로 새 버전으로 바꾸는 일. 이상하면 이전 버전으로 되돌려요.
헬스 체크
Health check
기구가 살아 있는지 주기적으로 찔러 보는 일. 여기서 멈추면 본부가 고장으로 판단해요.
