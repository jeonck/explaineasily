What is Indirect Prompt Injection?

Indirect prompt injection, told as a story about the chef reading a command hidden not by the guest, but on the ingredient wrapper.

The guest asked plainly — the note was sitting on the wrapper instead.The guest didn't write the note. The wrapper was already sitting in the pantry.

The chef reads whatever is on the wrapper as if the guest said it.The guest only said 'as the wrapper says'. Every word on that wrapper can become a command.

Indirect injection is a command hidden in outside material the model reads later.Not written by the guest — it was already waiting inside material the guest only pointed to.

On the pantry shelfhides inside an ingredient wrapper
In search results, web pagesinside material the chef goes to look up
In the results of an errandeven inside a document the runner brings back
No link back to the guestthe guest only pointed at the material

Direct injection is one path; indirect injection crosses two.Guest to material, material to chef. The attacker never even has to speak to the guest.

Direct and indirect injection differ only in where the command hides.The more errands fetch search results or documents, the more places there are to hide.

In one breath

Indirect prompt injection = a command hidden not by the guest, but in outside material the chef goes to read later — a wrapper, search results, a document.

An attack where an attacker's instructions sit inside content an LLM or agent fetches from outside — search results, a web page, a document — and get executed when the model reads it. The user never wrote or even saw the malicious text, which makes it harder to notice than direct injection.
