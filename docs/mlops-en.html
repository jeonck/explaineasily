What is MLOps/ModelOps?

MLOps, told as a story about an automatic proofing machine that must be kept teaching and watching, not just built once and forgotten.

The proofing machine built last year has been left untouched.It keeps missing today's expressions — the world moved on.

Unlike code, it learned from piles of examples — and that makes it harder to fix.So you can't just fix one line like ordinary code.

MLOps is continuously caring for the proofing machine.Keep teaching it, catch mistakes fast, and roll back to an older version if needed.

Gather new exampleskeep collecting recent manuscripts
Retrain itretrain the machine on the new examples
Watch for mistakescatch it as soon as accuracy drops
Roll back a versionif the new version is worse, revert

This care isn't a one-time pass — it loops continuously.Collect, retrain, test, swap, watch — then it starts over again.

A smarter machine isn't the end of the story.The tricky calls still go to a human proofreader. Caring for a borrowed big parrot instead is a different story → caring for the parrot.

In one breath

MLOps/ModelOps = not building the proofing machine once and walking away, but continuously retraining it on new manuscripts, watching for mistakes, and rolling back when needed.

MLOps (Machine Learning Operations) manages a machine learning model's data collection, training, validation, deployment, and monitoring as one repeating pipeline. ModelOps goes further, covering governance and auditing across many models in production. Because a model's behavior shifts with data rather than code, retraining and drift detection matter more here than in ordinary CI/CD.

When grown-ups say it

MLOps/ModelOps
The process of continuously caring for the machine. Not just building it — running it is part of the job too.
Data Pipeline
The path that brings in new manuscripts. A steady stream of training examples.
Retraining
Teaching the machine again with new material. When the world changes, the machine has to learn again.
Model Registry
The shelf that stores each version of the machine. Same idea as configuration management → the shelf that protects the manuscript.
Drift
The machine starting to miss things as the world changes. As the data shifts, accuracy quietly slips.
A/B Testing
Running the new machine and the old one side by side. Only the better one stays.
Model Rollback
If the new machine disappoints, go back. Same idea as the rewind in the theme-park world → resetting a ride to its old setup.
Monitoring
Keeping an eye on the machine's mistakes. It's the first thing to notice when accuracy drops.
