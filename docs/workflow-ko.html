워크플로가 뭐예요?

LLM 워크플로를 사람이 미리 적어 둔 순서표대로 앵무새가 칸마다 한 가지 일만 하는 이야기로 풀어봤어요.

매번 앵무새에게 번역하고, 요약하고, 표로 만들라고 다 맡겨요. 결과가 들쭉날쭉해요.월요일엔 번역이 빠지고, 화요일엔 표가 반쪽이에요. 같은 부탁인데 왜 다를까요?

왜냐면 한 번에 다 시키면 앵무새가 순서를 혼자 정하거든요. 그게 매번 달라요.한 장 쪽지에 일 세 가지가 들어 있으면 앵무새는 길을 매번 새로 골라요. 어떤 날은 한 가지를 빼먹어요.

워크플로는 사람이 미리 적어 둔 순서표예요. 앵무새는 칸마다 한 가지만 해요.번역 칸, 요약 칸, 표 칸. 칸마다 쪽지 하나, 하는 일 하나. 에이전트는 앵무새가 순서를 정하고, 워크플로는 사람이 정해요.

걸음마다 쪽지 하나한 칸엔 한 가지 일만
걸음 사이에 검사사람이나 기계가
정해진 일엔 순서표열린 일엔 에이전트
작은 앵무새로 충분쉬운 칸은 싸고 빠르게

칸 네 개가 한 줄로, 칸 사이마다 검사. 틀리면 그 칸만 다시 해요.같은 순서표를 돌리면 늘 같은 길로 가요. 쉬운 칸엔 작은 앵무새로 충분해요 — 어느 앵무새에게 맡길지는 이 이야기에서.

순서표는 예상 못 한 상황에 약해요. 그 자리엔 에이전트 칸을 하나 넣어요.정해진 일엔 순서표, 열린 일엔 에이전트. 칸이 많아지고 앵무새가 여러 마리면 앵무새 회의가 돼요.

한 줄로

워크플로 = 사람이 미리 적어 둔 순서표. 앵무새는 칸마다 한 가지만 하고, 칸 사이엔 검사가 있어요. 정해진 일엔 순서표, 열린 일엔 에이전트.

LLM workflow. 사람이 정해 둔 고정 순서(프롬프트 체이닝, 파이프라인)로 LLM 호출을 여러 단계 이어 붙이는 방식이에요. 단계마다 프롬프트 하나와 검증 단계를 두고, 실행이 결정적이라 재현·디버깅이 쉬워요. 에이전트는 모델이 순서를 정하고, 워크플로는 코드가 정해요. 단계별로 작은 모델을 라우팅하면 비용이 줄어요.

어른들은 이렇게 불러요

워크플로
Workflow
심부름 순서표. 사람이 걸음 순서를 미리 정해요. 앵무새는 칸마다 한 가지만.
프롬프트 체이닝
Prompt chaining
쪽지를 줄줄이. 앞 칸의 답이 다음 칸의 쪽지에 들어가요.
파이프라인
Pipeline
한 줄 순서표. 칸이 한 줄로 쭉 이어진 순서표예요. 갈림길이 없어요.
라우팅
Routing
어느 앵무새에게 맡길까. 쉬운 칸은 작은 앵무새에게. → 어느 앵무새에게 시킬까
에이전트와의 차이
Difference from an agent
순서를 누가 정하나. 워크플로는 사람이, 에이전트는 앵무새가. → 심부름 목록을 스스로 짜는 앵무새
결정적 실행
Deterministic execution
늘 같은 길. 같은 순서표를 돌리면 같은 길로 가요. 틀리면 어느 칸인지 바로 알아요.
검증 단계
Validation step
칸 사이 검사. 사람이나 기계가 봐요. 틀리면 그 칸만 다시.
오케스트레이션
Orchestration
칸이 많고 앵무새가 여럿. 누가 언제 뭘 할지 정하는 일. → 앵무새 회의
