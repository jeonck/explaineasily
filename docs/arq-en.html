In one breath

ARQ (Automatic Repeat reQuest) is an error-control method where the receiver checks the message and automatically asks for a resend when it's wrong.

ARQ detects errors with a checksum/CRC, then resends bad data based on acknowledgment responses (ACK/NACK). Stop-and-Wait, Go-Back-N, and Selective Repeat are the three classic variants — throughput improves down the list, at the cost of more complex implementation and buffer management. Because resending itself adds delay, delay-sensitive data like live voice or video often just drops errors or pairs ARQ with other methods like FEC (forward error correction).

When grown-ups say it

ARQ
The method that asks for a resend when wrong. Works by exchanging acknowledgments.
Stop-and-Wait
The simplest variant — send one, then wait. Simple, but slow.
Go-Back-N
Resends everything after a bad one. Faster than Stop-and-Wait, but wasteful.
Selective Repeat
Resends only the bad packets. Most efficient, but most complex.
Checksum / CRC
The check value that tells if a message is wrong. What ARQ uses to decide whether to resend.
ACK/NACK
The 'got it' and 'that's wrong' signals. The core signals that drive ARQ.
Forward Error Correction
A different approach that fixes errors without resending. Better suited to delay-sensitive data.
MEC
Computing nearby to cut latency. A different approach to shrinking the delay itself. → the MEC booth
