CPU vulnerabilities like Meltdown and Spectre, told as a story about the trace left behind by a worker who guesses ahead.

In one breath

The CPU vulnerabilities Meltdown and Spectre = flaws where a CPU that guesses ahead leaves a trace in its cache even on a wrong guess — a trace that can be read back to leak information.

Meltdown and Spectre (disclosed in 2018) are hardware vulnerabilities that abuse speculative execution, an optimization in modern CPUs. A CPU predicts and runs upcoming instructions ahead of time; if the prediction is wrong, the results are discarded, but the memory it touched along the way leaves a trace in the cache. An attacker can measure tiny differences in cache-access timing — a side-channel attack — to indirectly read kernel memory (Meltdown) or another process's memory (Spectre). Microcode and OS patches mitigate the issue but cost performance, and because the design trade-off is fundamental, it can't be eliminated completely.

When grown-ups say it

Speculative execution
Doing the work before being asked. The core trick that makes a CPU fast. A wrong guess only discards the result.
Cache timing
The trace left in the shelf. Memory that was peeked at sits in the cache, so reading it again is faster — that speed gap gives away the trace.
Side-channel attack
Reading the trace by measuring it. Not a direct theft — it infers the secret from an indirect signal like timing.
Meltdown
Peeking all the way into the vault (kernel). Speculatively reaches into memory that should be completely off-limits.
Spectre
Tricking the worker into peeking at another guest's room. Tricks the program itself into guessing wrong. Harder to fully block than Meltdown.
Microcode/OS patch
A patch boarding up the shelf. Fixed jointly by the chipmaker and the OS. → the board the carpenter sent
Performance cost
Guess less, and it slows down. A straight trade-off between safety and speed.
Hardware vulnerability
A gap in the CPU's own design. A gap that a software patch alone can't fully close.
