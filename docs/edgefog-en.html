What is Edge and Fog Computing?

Edge and fog computing, told as a story about a local branch — and a hub in between — handling things before the far-off HQ has to.

A visitor from across town takes forever to reach HQ.The wait grows right along with the distance.

Funnel everyone into one HQ, and the wait grows.There needs to be a way to handle it closer by.

Edge = the local branch, fog = the hub between it and HQ.Handling things closer by makes it faster.

The nearest spot handles it firstedge = the local branch
Fog bundles several branches togetherit's the hub between branch and HQ
The shorter the distance, the fasterresponse latency drops
It still has to sync with HQ eventuallysynchronization is required

Roles split depending on where processing happens.Simple things stay close; heavy things go to HQ.

The branch is too small to hold everything.It still has to sync back up with HQ eventually.

In one breath

Edge computing means handling things right at the nearby local branch. Fog computing is the hub in between that bundles those branches together. Both shorten the distance to the central HQ.

Edge computing processes data right next to where it's generated (e.g. right beside an IoT sensor). Fog computing adds a layer between the edge and the central cloud, bundling multiple edge nodes together. Both cut latency and reduce load on the central network, but HQ — the central cloud — still has far greater processing capacity and storage reach.

When grown-ups say it

Edge computing
Processing right at the small local branch. Right next to where the data is generated.
Fog computing
The middle hub bundling several branches. One more layer, between edge and HQ.
Latency
The wait that grows with distance. Shorter, the closer it is.
Synchronization
Matching branch data back up with HQ. Needed because the branch alone can't hold it all.
IoT
The devices out in the field generating data. The thing edge computing processes right next to.
Central cloud (HQ)
The HQ building handling full storage and heavy analysis. The very building this whole book is set in. → the shared office building
Serverless
The meeting room that opens only when used. Serverless functions are sometimes placed at the edge too. → the hourly meeting room
Auto scale
Automatically adding more branches. Edge branch count can also scale with demand. → bigger office or more offices
