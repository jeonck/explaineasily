LOD·오픈 데이터가 뭐예요?

LOD(연계 공개 데이터)와 오픈 데이터를, 문을 열고 표준 번호표를 달아 서로 연결해두는 창고 이야기로 풀어봤어요.

이 창고 안에 뭐가 있는지 아무도 몰라요.문이 잠겨 있고, 안내문도 없어요.

공개는 했지만 프로그램이 읽을 수 없어요.형식이 제각각이면 다시 쓰기 어려워요.

LOD/오픈 데이터 = 문을 열고, 표준 번호표를 달고, 끈으로 연결해 공개하는 것이에요.누구나 와서 꺼내 쓸 수 있어요.

문 열기누구나 볼 수 있게 공개해요
표로 정리하기구조를 갖춰요
표준 번호표 달기프로그램 특정 형식에 안 묶여요
다른 창고와 연결하기끈으로 이어 더 풍부해져요

공개 데이터는 이 네 단계를 거쳐 좋아져요.마지막 단계가 바로 LOD(연계 공개 데이터)예요.

공개한다고 품질까지 보장되진 않아요.공개는 형식의 문제지, 내용의 정확함을 보장하진 않아요.

한 줄로

오픈 데이터/LOD = 창고 문을 누구나 볼 수 있게 열고, 상자에 표준 번호표(URI)를 달아 다른 창고와 끈으로 연결해 공개하는 것.

오픈 데이터는 누구나 자유롭게 접근·재사용·재배포할 수 있게 공개한 데이터이고, LOD(Linked Open Data)는 팀 버너스리가 제안한 5성 등급 중 최상위 단계로, 데이터에 URI를 부여하고 RDF 등으로 다른 데이터와 링크를 맺어 '연결된 공개 데이터망'을 만드는 것이에요. 공개 여부와 품질·최신성은 별개의 문제예요.

어른들은 이렇게 불러요

오픈 데이터
Open Data
누구나 쓸 수 있게 연 창고. 라이선스까지 명확해야 진짜 오픈이에요.
LOD(연계 공개 데이터)
Linked Open Data
번호표를 달아 서로 연결한 창고. 5성 등급 중 가장 높은 단계예요.
5성 등급
5-Star Open Data
창고가 좋아지는 다섯 단계. 별이 늘수록 재사용이 쉬워져요.
URI
URI
상자마다 달린 표준 번호표. 프로그램이 서로 가리킬 수 있게 해요.
RDF
RDF
상자와 상자를 잇는 끈의 규칙. 주어-서술어-목적어 형태로 적어요.
NoSQL 모델링
NoSQL Modeling
상자 모양에 맞춰 선반을 바꾸는 창고. 그래프형 NoSQL은 연결 표현에 잘 맞아요. → 자유로운 선반 창고
정규화
Normalization
선반 한 칸에 한 번만 적는 규칙. 공개 데이터도 중복을 줄이면 더 다루기 쉬워요. → 한 칸에 한 번만 적는 규칙
