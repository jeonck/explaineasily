가상머신(VM)과 컨테이너가 뭐예요?

가상머신(VM)과 컨테이너를, 공유 오피스 빌딩에서 독채로 할지 칸막이로 할지의 차이로 풀어봤어요.

입주사는 자기만의 공간이 필요해요, 근데 방법이 두 가지예요.완전히 따로 쓸지, 가볍게 나눠 쓸지예요.

칸막이가 가볍다고 독채만큼 완전히 분리된 건 아니에요.칸막이 책상은 바닥(OS)을 같이 써요.

VM = 독채 사무실, 컨테이너 = 칸막이 책상이에요.둘 다 '내 공간'을 나누는 방법이지만 무게가 달라요.

독채는 입주(부팅)가 느려요바닥부터 다 짓거든요
독채는 벽이 완전히 따로예요격리가 더 확실해요
칸막이는 가볍고 빨라요바닥을 같이 쓰니까요
칸막이는 옆 칸 소음이 넘어와요자원 경합이라고 불러요

독채와 칸막이는 네 가지 기준에서 갈려요.가벼움과 완전한 분리는 맞바꾸는 관계예요.

실제로는 섞어 쓰고, 자동 배정이 어디에 세울지 정해요.독채 vs 칸막이는 양자택일이 아니에요.

한 줄로

VM = 바닥(OS)부터 따로인 독채 사무실. 컨테이너 = 바닥을 같이 쓰는 가벼운 칸막이 책상. 분리 수준과 무게를 맞바꿔요.

가상머신(VM)은 하이퍼바이저 위에 OS까지 통째로 가상화해 완전한 격리를 주지만 무겁고 부팅이 느려요. 컨테이너는 호스트 OS 커널을 공유하며 프로세스 단위로 격리해 가볍고 빠르지만, 격리 수준은 VM보다 낮아요. 실무에선 보통 컨테이너 여러 개를 VM 안에서 돌려요.

어른들은 이렇게 불러요

가상머신(VM)
Virtual Machine
바닥(OS)부터 완전히 따로인 독채 사무실. 격리는 확실하지만 무겁고 느려요.
컨테이너
Container
바닥(OS)을 같이 쓰는 칸막이 책상. 가볍고 빠르지만 격리는 더 약해요.
하이퍼바이저
Hypervisor
한 건물 터에 여러 독채를 세워주는 시공사. VM을 가능하게 하는 바탕 기술이에요.
자원 경합
Resource contention
옆 칸 소음이 벽을 넘어오는 것. 컨테이너가 바닥을 같이 쓰면서 생기는 트레이드오프예요.
이미지(컨테이너 이미지)
Container image
똑같이 찍어낸 책상 세트. 성 세계에서는 짐칸이라고 불러요. → 똑같이 찍어낸 짐칸
오케스트레이션
Orchestration
어디에 몇 칸 세울지 정하는 관리사무소. 독채·칸막이를 실제로 배치하는 역할이에요. → 자동 좌석 배정 배지
서버리스
Serverless
아예 입주할 필요도 없는 시간제 회의실. 독채·칸막이보다 한 단계 더 가벼워요. → 시간제 회의실
스케일 업/아웃
Scale-up / Scale-out
사무실을 키울지, 더 빌릴지. 독채는 스케일업, 칸막이는 스케일아웃에 더 잘 맞아요. → 사무실을 키울까 더 빌릴까
