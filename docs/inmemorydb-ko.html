인메모리 컴퓨팅(In-Memory DB/IMDG)이 뭐예요?

인메모리 DB와 IMDG를, 깊은 선반까지 안 가고 바로 꺼내는 특급 출고대 이야기로 풀어봤어요.

저 안쪽 깊은 선반까지 다녀와야 해요.그동안 배송 기사는 계속 기다려요.

같은 인기 상품인데 매번 깊은 선반까지 가요.자주 찾는 건 가까이 둘 수 없을까요?

인메모리 DB = 깊은 선반 대신 바로 꺼내는 특급 출고대예요.메모리에 올려두니 꺼내는 데 거의 시간이 안 걸려요.

메모리에 바로 두기디스크까지 안 가요
빠른 꺼내기지연이 거의 없어요
휘발성 위험전원 나가면 사라져요
IMDG — 여러 대 묶기메모리를 모아 더 크게 써요

인메모리 DB/IMDG는 이렇게 쓰여요.휘발성은 로그나 스냅샷으로 보완해요.

메모리는 비싸서 전부 다 올릴 순 없어요.그래서 자주 쓰는 것만 골라 올려요(캐시).

한 줄로

인메모리 DB/IMDG = 깊은 선반(디스크)까지 가지 않고, 메모리에 바로 올려 둬서 거의 지연 없이 꺼내 쓰는 방식.

인메모리 DB는 디스크가 아닌 주기억장치(RAM)에 데이터를 상주시켜 I/O 지연을 없애는 데이터베이스이고, IMDG(In-Memory Data Grid)는 여러 노드의 메모리를 묶어 분산된 대용량 인메모리 저장소로 쓰는 것이에요. 휘발성이 약점이라 로그 선행기록(WAL)·스냅샷·복제로 내구성을 보완해요.

어른들은 이렇게 불러요

인메모리 DB
In-Memory Database
메모리에 바로 데이터를 두는 창고. 디스크 I/O 지연이 거의 없어요.
IMDG
In-Memory Data Grid
여러 대의 메모리를 묶은 창고. 샤딩과 함께 규모를 키워요. → 구역으로 쪼갠 창고
캐시
Cache
자주 찾는 것만 가까이 두는 것. 전부가 아니라 일부만 올려요.
휘발성
Volatility
전원이 나가면 사라지는 성질. 로그/스냅샷으로 복구해요.
지속성(Durability)
Durability
도장 찍히면 사라지지 않는 약속. 인메모리 DB는 이 약속을 일부 타협해요. → 전표가 지키는 네 약속
NoSQL 모델링
NoSQL Modeling
상자 모양에 맞춰 선반을 바꾸는 창고. Key-Value형과 자주 함께 쓰여요. → 자유로운 선반 창고
캐싱(놀이공원 세계)
Caching (Amusement-Park World)
놀이공원 세계에서 다루는 캐시 이야기. 분산 시스템 관점의 캐싱은 그쪽에서 더 다뤄요. → 캐싱
병행제어
Concurrency Control
동시에 손대도 안 부딪히게 막는 규칙. 메모리 위에서도 이 규칙은 그대로 필요해요. → 동시에 안 부딪히는 규칙
