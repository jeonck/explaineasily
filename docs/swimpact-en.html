What is a Software Project Impact Assessment?

Impact assessment, told as a story about mapping how far a change to book one will ripple into the rest of the series before you make it.

Only book one changed, but now book two contradicts it.One small setting change rippled through the rest of the story.

The bigger the series, the harder it is to see the links.Nobody knows what will shake loose with each change.

Impact assessment maps the connections before you change anything.Before changing book one, first check how far it reaches.

Grade the riskbigger ripples get a higher risk grade
Check who's affectedsee which readers are affected

Impact gets written down by grade.Direct, indirect, and unaffected — sorted this way, it's clear where to start.

Impact assessment doesn't solve everything.Do it too often and you slow down; too rarely and accidents happen. The right balance is set together with → the last checker before publication.

In one breath

Software project impact assessment = before changing one book in a series, drawing a connection map of how far it spreads and how risky that is.

A software project impact assessment analyzes, before changing an existing information system, how far and how severely that change reaches related work, systems, and stakeholders. It separates direct from indirect impact, assigns a risk grade, and uses the result to adjust the scope, schedule, and resourcing of the change.

When grown-ups say it

Impact Assessment
The connection map drawn before a change. Gauges scope and risk ahead of time.
Impact Scope Analysis
Circling how far the ripple could reach. Separates direct impact from indirect.
Stakeholder Analysis
Checking which readers are affected. Decides who needs to be told in advance.
Traceability
The thread running from requirement to code. Without this thread, you can't trace how far an impact runs.
Risk Grade
The grade assigned to how big the ripple is. The higher it is, the closer the review needs to be.
Regression Testing
Re-checking the parts that used to be fine, after a change. The step that actually verifies the scope impact assessment identified.
Change Management
The process deciding whether and when to make the change. The impact assessment result is what this decision is based on.
Governance
The framework for who approves this kind of decision. The bigger the impact, the higher up it needs sign-off.
