In one breath

Divide-and-conquer splits a problem and combines the results, greedy always picks the best choice right now, and dynamic programming remembers an already-solved answer instead of re-solving it.

Divide-and-conquer splits a problem into independent smaller subproblems, solves each, and combines the results (e.g., merge sort). Greedy repeatedly picks whatever choice looks best at each step without considering the whole picture — fast, but not always globally optimal (though for some problems, like minimum spanning trees, it is). Dynamic programming stores the result of a subproblem once computed (memoization) and reuses it, avoiding redundant recomputation — suited to problems with optimal substructure and overlapping subproblems. All three handle a big problem in smaller pieces, but they differ in how they treat those pieces.

When grown-ups say it

Divide and Conquer
Splitting a problem, solving the pieces, then combining. Sorting gives a concrete example. → different ways to line cars up by size
Greedy Algorithm
Picking whatever looks best right now, every time. Actually provably optimal for connecting everything cheaply. → piping every branch together for the least cost
Dynamic Programming
Remembering an already-solved answer and reusing it. Never solves the same subproblem twice.
Memoization
The technique of storing a result once it's computed. The way dynamic programming is actually implemented.
Optimal Substructure
The property that optimal sub-answers combine into the optimal whole. Dynamic programming only works when this property holds.
Overlapping Subproblems
The same small problem showing up again and again. Memoization only pays off when this is present.
Backtracking
Backing up and trying another path when stuck. Yet another strategy for tackling a big problem.
Time Complexity (Big-O)
The ruler that measures how much slower things get as a problem grows. All three methods are compared using this same ruler. → how much slower as cars pile up
