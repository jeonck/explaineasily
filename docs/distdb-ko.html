분산 데이터베이스가 뭐예요?

분산 데이터베이스를, 하나의 거대한 창고 대신 여러 지역 지점으로 나눠 서로 맞춰가는 이야기로 풀어봤어요. 깊은 분산 이론은 SRE 세계에서 더 다뤄요.

전국 모든 주문이 창고 하나로만 몰려요.창고가 멀면 배송도 느려요.

그냥 다 복제해두면 되는 거 아냐?동시에 고치면 복제본끼리 틀어져요.

분산 데이터베이스는 여러 지점으로 나눈 창고 네트워크예요.가까운 지점에서 빠르게, 그래도 전체는 하나처럼 보이게.

지역별로 나누기샤딩/파티셔닝이에요
복제해서 안전하게지점 하나가 쉬어도 돼요
합의로 맞추기여럿이 투표해 정해요
적당한 지연 받아들이기완벽한 동시성 대신요

중앙집중 vs 분산, 속도와 정합성을 맞바꿔요.시험에서는 이 트레이드오프를 자주 물어요.

나누기·복제·합의는 분산 DB 모델링의 기본기예요.분산 이론 자체는 SRE 세계에서 더 깊이 다뤄요.

한 줄로

분산 데이터베이스는 하나의 논리적 DB를 여러 지점(노드)에 나눠 저장하고, 복제와 합의로 하나처럼 보이게 맞추는 구조예요.

DB 모델링 시험 관점에서는 데이터를 어떻게 나눌지(샤딩 키 설계), 어떻게 복제할지(동기/비동기), 조인·트랜잭션 비용이 어떻게 늘어나는지를 다뤄요. CAP 정리·합의 알고리즘 같은 분산 시스템 이론 자체는 SRE 세계의 관련 페이지에서 더 깊이 설명해요.

어른들은 이렇게 불러요

샤딩
Sharding
지점별로 나눠 담기. 나누는 기준(키) 설계는 이 세계에서 더 다뤄요. → 너무 커진 창고를 구역으로 쪼개기
복제
Replication
지점마다 복제 상자 두기. 동기/비동기 복제의 차이를 다뤄요. → 복제 상자의 세계
합의 알고리즘
Consensus
여럿이 투표해서 하나로 정하기. Raft/Paxos 같은 알고리즘을 다뤄요. → 여러 명이 투표로 정하기
CAP 정리
CAP Theorem
셋 다 완벽히는 못 가져요. 일관성·가용성·분단내성의 트레이드오프예요. → 세 가지를 동시에 가질 수 없는 법칙
최종적 일관성
Eventual Consistency
조금 늦게라도 결국 맞춰짐. 당장은 숫자가 달라도 돼요. → 결국엔 맞춰지는 이야기
데이터 지역성
Data Locality
가까운 지점에서 처리하기. 가까울수록 응답이 빨라요.
분산 트랜잭션(2PC)
Distributed Transaction (2PC)
여러 지점에 걸친 출납 전표. 모든 지점이 동의해야 확정돼요.
NoSQL
NoSQL
고정된 선반 칸이 아닌 창고. 분산에 유리하게 구조를 느슨하게 둬요.
