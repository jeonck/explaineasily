관계 무결성 제약이 뭐예요?

관계 무결성 제약을, 학생 명부에 있는 이름만 반장 명단에 쓸 수 있다는 학생회 규칙 이야기로 풀어봤어요.

반장 명단에 학생 명부엔 없는 이름이 있어요.원본에 없는 이름을 참조 명단에 적어버린 거예요.

없는 사람이 반장이면 나중에 꼬여요.존재하지 않는 학생이 반장으로 등록되면 확인할 때 꼬여요.

관계 무결성은 원본에 있는 이름만 참조 명단에 쓸 수 있다는 규칙이에요.없는 이름을 적으려 하면 아예 등록이 막혀요.

원본에 있어야 참조 가능없는 이름은 못 적어요
같이 지우기(CASCADE)원본이 사라지면 참조도 지워요
못 지우게 막기(RESTRICT)참조가 있으면 못 지워요
빈 칸 처리(SET NULL)참조 칸만 비워둬요

원본이 사라지면 세 가지 중 하나를 고를 수 있어요.상황에 맞게 세 옵션 중 하나를 미리 정해둬요.

너무 엄격하면 불편해요.너무 엄격한 규칙(RESTRICT)은 평소 일 처리를 불편하게 만들 수 있어요.

한 줄로

관계 무결성 제약 = 참조하는 자료는 반드시 원본에 실제로 있는 값이어야 한다는 규칙. 원본이 사라질 때 지우거나, 막거나, 비우는 방식을 미리 정해둬요.

관계 무결성 제약은 관계형 데이터베이스에서 외래키(FK)가 반드시 참조 대상 테이블의 기본키(PK)에 실제로 존재하는 값이어야 한다는 제약이에요. 원본 행이 삭제·수정될 때는 CASCADE(함께 삭제/수정), RESTRICT(삭제 자체를 금지), SET NULL(참조 값을 NULL로) 중 하나를 옵션으로 정해 데이터 일관성을 지켜요.

어른들은 이렇게 불러요

관계 무결성 제약
Referential Integrity Constraint
참조는 원본에 있는 값이어야 한다는 규칙. 관계형 데이터베이스의 기본 일관성 규칙이에요.
외래키(FK)
Foreign Key (FK)
다른 명부를 가리키는 칸. 원본 명부의 기본키를 가리켜야 해요.
기본키(PK)
Primary Key (PK)
명부에서 한 사람을 딱 가리키는 번호. 외래키가 가리키는 대상이에요.
CASCADE
CASCADE
원본이 사라지면 참조도 같이 지우는 것. 자동으로 정리되지만, 의도치 않게 많이 지워질 수도 있어요.
RESTRICT
RESTRICT
참조가 있으면 원본을 못 지우게 막는 것. 안전하지만 가끔 불편해요.
SET NULL
SET NULL
참조 칸만 비워두는 것. 원본은 지우되 참조 기록은 남겨요.
정규화
Normalization
명부를 한 번만 적도록 나누는 규칙. 참조 무결성은 정규화된 명부 사이의 규칙이에요. → 한 칸에 한 번만 적는 규칙
트랜잭션
Transaction
명부를 바꾸는 작업의 단위. 제약을 어기면 트랜잭션 전체가 취소돼요.
