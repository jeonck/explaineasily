디자인 씽킹이 뭐예요?

디자인 씽킹을, 책상에서 추측하는 대신 독자를 직접 만나 돌고 도는 편집장의 이야기로 풀어봤어요.

이 책, 왜 안 팔리지?편집장은 이유를 몰라요.

책상에서 혼자 추측만 해요.독자를 직접 만나 본 적은 없어요. 추측은 자주 빗나가요.

디자인씽킹은 독자를 직접 만나, 묻고 만들고 다시 고치길 반복하는 과정이에요.책상 추측이 아니라, 돌고 도는 현장 확인이에요.

공감하기독자를 직접 만나요
문제 다시 정의하기진짜 헷갈리는 지점을 찾아요
아이디어 쏟아내기일단 많이 내봐요
싼 시제품으로 먼저 보여주기독자 반응 보고 다시 고쳐요

다섯 단계가 원을 그리며 돌고 돌아요.한 바퀴 돌고 나면, 다시 공감으로 돌아가요.

디자인씽킹이 전부를 대신하진 않아요.무엇을 쓸지 찾는 방법이지, 모든 공정을 대신하진 않아요.

한 줄로

디자인 씽킹 = 책상 추측 대신 독자를 직접 만나, 공감·정의·아이디어·시제품·테스트를 돌고 도는 문제 해결법.

디자인 씽킹은 사용자(독자) 공감에서 출발해, 문제를 재정의하고, 많은 아이디어를 내고, 값싼 시제품을 만들어, 실제 사용자에게 테스트한 뒤 다시 공감 단계로 돌아가는 사람 중심·반복적 설계 방법론이에요. 결과물을 어떻게 만들지보다, 무엇을 만들어야 하는지를 먼저 찾는 데 집중해요.

어른들은 이렇게 불러요

디자인씽킹
Design Thinking
추측 대신 독자를 직접 만나는 문제 해결법. 다섯 단계를 돌고 또 돌아요.
공감(Empathize)
Empathize
독자를 직접 만나는 첫 단계. 책상 추측을 멈추는 지점이에요.
문제 정의(Define)
Define
진짜 헷갈리는 지점을 다시 짚는 단계. '좋은 책'이 아니라 구체적인 문제로 좁혀요.
아이디어 발산(Ideate)
Ideate
일단 많이 쏟아내는 단계. 좋고 나쁨은 나중에 걸러요.
프로토타입(Prototype)
Prototype
싼값에 빨리 만든 샘플 페이지. 완성본이 아니라 확인용이에요.
요구공학
Requirements Engineering
쓰기 전에 먼저 묻는, 더 체계적인 절차. 디자인씽킹의 공감·정의를 더 깊게 파고들어요. → 쓰기 전에 먼저 묻는 사람
A/B 테스트
A/B Test
두 안 중 뭐가 더 잘 통하는지 숫자로 재는 시험. 디자인씽킹의 테스트 단계를 통계적으로 더 깊게 들어가요. → 두 표지 중 뭐가 진짜 더 잘 팔릴까
사용성평가
Usability Test
시제품을 실제로 써보게 하고 지켜보는 일. 테스트 단계에서 자주 같이 써요. → 독자가 책을 쓱 넘겨보는 시험
