페이징·세그멘테이션이 뭐예요?

페이징과 세그멘테이션을, 학교 사물함(고정 크기)과 준비물 창고(제각각 크기)를 나누는 두 가지 다른 방식 이야기로 풀어봤어요. (컴퓨터 구조 주제라 학생회 규칙과는 결이 조금 달라요 — 기술 깊이는 ppesys의 가상메모리 페이지로.)

사물함은 다 똑같은 크기인데, 준비물 크기는 제각각이에요.작은 것도, 큰 것도 똑같은 칸에 넣어야 해요.

고정 크기로만 자르면 공간이 남거나 모자라요.한 가지 방식만 쓰면 공간이 새거나, 물건이 흩어져요.

페이징과 세그멘테이션은 창고를 나누는 두 가지 다른 방식이에요.둘 다 '진짜 창고가 좁아도 넉넉해 보이게' 나누는 방법이에요.

페이징 — 같은 크기로몇 번째 칸인지로 찾아요
세그멘테이션 — 의미로코드·데이터처럼 역할로 나눠요
둘 다 가짜 지도실제 위치는 따로 관리돼요
섞어 쓰기도 해요세그멘테이션 안을 다시 페이징해요

두 방식을 나란히 비교하면 이렇게 달라요.실제 시스템은 둘을 섞어 쓰기도 해요.

둘 다 '가짜 지도'일 뿐, 진짜 관리는 다른 세계에서 다뤄요.이 페이지는 두 방식의 차이만, 실제 반장(OS)의 관리는 ppesys에서 다뤄요.

한 줄로

페이징은 메모리를 고정 크기 칸으로, 세그멘테이션은 의미 단위(코드/데이터 등)로 나누는, 가상 주소를 실제 메모리에 대응시키는 두 가지 다른 방식.

페이징은 가상·물리 메모리를 모두 고정 크기(페이지/프레임)로 나누고 페이지 테이블로 매핑해요. 구현이 단순하고 외부 단편화가 없지만, 마지막 페이지가 다 안 차면 내부 단편화가 생겨요. 세그멘테이션은 프로그램을 코드·데이터·스택처럼 의미 있는 단위(세그먼트)로 나누는데, 세그먼트 크기가 제각각이라 보호·공유는 쉽지만 세그먼트 사이에 외부 단편화가 생길 수 있어요. 현대 운영체제는 흔히 세그먼트 안을 다시 페이징하는 방식(세그멘테이션 페이징)을 써요.

어른들은 이렇게 불러요

페이징
Paging
고정 크기 칸으로 자르는 방식. 물리적 위치 기준으로 주소를 매겨요.
세그멘테이션
Segmentation
의미 단위로 자르는 방식. 코드·데이터·스택처럼 역할로 나눠요.
내부 단편화
Internal Fragmentation
고정 칸 안에 남는 자투리 공간. 페이징에서 생기기 쉬워요.
외부 단편화
External Fragmentation
칸과 칸 사이에 생기는 못 쓰는 빈틈. 세그멘테이션에서 생기기 쉬워요.
페이지 테이블
Page Table
가상 칸과 진짜 칸의 대응표. 페이징의 핵심 구조예요. → 창고 전체를 내 것처럼 보여주는 가짜 지도
세그먼트 테이블
Segment Table
세그먼트마다 시작 위치와 길이를 적은 표. 세그먼트는 크기가 다 달라서 길이도 같이 적어요.
세그멘테이션 페이징
Segmented Paging
세그먼트 안을 다시 페이징하는 혼합 방식. 두 방식의 장점을 같이 쓰려는 거예요.
가상메모리
Virtual Memory
실제보다 넉넉해 보이게 하는 가짜 지도 전체 개념. 페이징·세그멘테이션은 이걸 구현하는 두 방법이에요. → 가상메모리·페이징
