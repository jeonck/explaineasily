접근통제 모델이 뭐예요?

접근통제 모델(DAC·MAC·RBAC)을, 성의 방마다 열쇠를 누가 정하는지 다른 세 가지 규칙 이야기로 풀어봤어요.

방마다 열쇠 주는 규칙이 제각각이에요.어떤 방은 주인 맘대로, 어떤 방은 왕의 등급표대로, 어떤 방은 역할(모자)대로예요.

규칙을 안 정하면 섞여서 사고가 나요.방 주인 맘대로 줬는데 알고 보니 왕의 비밀 방이었어요. 어떤 규칙을 쓸지 먼저 정해야 해요.

접근통제 모델은 열쇠 결정권을 누구에게 두는지의 규칙이에요.MAC의 등급표는 정확한 규칙이 따로 있고, RBAC는 이미 모자마다 열쇠 꾸러미로 자세히 다뤘어요.

DAC방 주인이 직접 정해요
MAC왕의 등급표, 아무도 못 바꿔요
RBAC모자(역할)에 열쇠를 줘요
섞어서 써요한 성이 셋을 같이 쓰기도 해요

셋을 나란히 놓고 보면 이래요.결정권자가 다르면 유연성과 위험도 달라져요. 시험은 이 분류 자체를 자주 물어봐요.

하나만으로는 부족해요.실제로는 여러 모델을 섞어 써요. → RBAC, ABAC, MAC의 정확한 규칙은 BLP/Biba에서 다뤄요.

한 줄로

접근통제 모델은 '열쇠를 누가 결정하나'의 규칙이에요. DAC는 방 주인이, MAC는 왕의 등급표가, RBAC는 모자(역할)가 정해요.

Discretionary Access Control(DAC)은 자원 소유자가 재량으로 권한을 부여하고, Mandatory Access Control(MAC)은 중앙에서 정한 보안 등급(레이블)을 소유자도 바꿀 수 없으며, Role-Based Access Control(RBAC)은 역할에 권한을 묶고 사용자에게 역할만 부여해요. 기술사 시험에서는 이 셋의 결정권자·유연성·적용 사례를 비교하는 문제가 자주 나와요.

어른들은 이렇게 불러요

DAC
Discretionary Access Control
방 주인이 직접 정해요. 유연하지만, 주인이 실수하면 바로 사고로 이어져요.
MAC
Mandatory Access Control
왕의 등급표, 아무도 못 바꿔요. 자세한 읽기·쓰기 규칙은 따로 있어요. → 접근통제 보안 모델(BLP/Biba)
RBAC
Role-Based Access Control
모자(역할)에 열쇠를 줘요. 가장 흔히 쓰는 방식이에요. → 모자마다 열쇠 꾸러미
ABAC
Attribute-Based Access Control
문지기의 조건 문장. 꼬리표(속성) 여러 개를 조합해요. → 문지기의 조건 문장
보안 등급(레이블)
Security label
왕의 등급 도장. MAC에서 방과 사람 모두에게 붙는 고정 등급이에요.
최소 권한
Least privilege
딱 필요한 열쇠만. 어느 모델을 쓰든 지켜야 하는 원칙이에요. → 딱 필요한 열쇠만
감사(Audit)
Audit
누가 왜 그 열쇠를 가졌는지 확인. 규칙이 분명해야 검사관도 점검할 수 있어요. → 이웃 나라 규칙 검사관
혼합 모델
Hybrid model
세 모델을 같이 쓰는 성. 실제 조직은 DAC·MAC·RBAC·ABAC를 상황별로 섞어 써요.
