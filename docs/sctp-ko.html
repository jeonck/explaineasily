SCTP가 뭐예요?

한 배송 계약 안에 시리즈별 전용 차선을 둬서, 하나가 막혀도 나머지는 그대로 가게 하는 이야기예요.

여러 시리즈를 한 트럭에 다 실어서 보내요.한 줄로 묶여서 가요.

하나가 막히면 전부 막혀요.한 줄로 묶여 있으면, 한 시리즈의 사고가 다른 시리즈까지 막아요.

SCTP = 하나의 계약 안에 시리즈별 전용 차선을 두는 거예요.동화 차선이 막혀도 만화·잡지 차선은 그대로 가요.

스트림별 독립 배달한 시리즈 지연이 다른 걸 안 막아요
메시지 경계 보존책 한 권 단위로 딱 배달돼요
다중 경로(멀티호밍)길이 끊기면 대체 도로로
차선 안에서는 순서 보장그래도 배달 확인은 그대로예요

TCP, UDP와 나란히 놓고 보면 차이가 보여요.SCTP는 TCP의 신뢰성과, 막히지 않는 병렬성을 같이 가져가요.

설계는 좋지만, 널리 쓰이진 않아요.방화벽·중간 장비 호환성 문제로, 실제로는 SIGTRAN 같은 특정 용도에 더 많이 쓰여요.

한 줄로

SCTP = 하나의 연결(association) 안에 여러 독립적인 스트림(차선)을 두고, 다중 경로(멀티호밍)로 안정성까지 챙긴 전송 프로토콜.

SCTP(Stream Control Transmission Protocol)는 TCP처럼 신뢰성 있고 순서가 보장되는 전송을 제공하면서도, 하나의 연결(association) 안에 여러 스트림을 둬서 한 스트림의 지연이 다른 스트림을 막는 head-of-line blocking을 피해요. 또 여러 IP 주소로 동시에 연결해(멀티호밍) 한 경로가 끊겨도 통신을 이어갈 수 있어요. 메시지 경계도 보존해, TCP처럼 바이트 스트림을 직접 잘라 쓸 필요가 없어요.
