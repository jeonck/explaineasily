스케일업/스케일아웃과 오토스케일이 뭐예요?

스케일업·스케일아웃·오토스케일을, 사무실을 키울지 더 빌릴지, 그걸 자동으로 맡길지의 이야기로 풀어봤어요. 이 건물 투어의 마지막 페이지예요.

일이 늘면 사무실 하나로는 부족해져요.더 넓은 공간이 필요해져요.

키울지, 더 빌릴지 — 방법이 두 가지라 헷갈려요.둘 다 '더 넓어진다'는 결과는 같아요.

스케일업 = 한 칸을 키우기, 스케일아웃 = 칸 수를 늘리기예요.하나를 세게 키우거나, 여러 개로 나누거나예요.

스케일업 = 한 칸을 더 크게수직 확장이라고 불러요
스케일아웃 = 칸 수를 더 많이수평 확장이라고 불러요
둘 다 자동으로 맡길 수 있어요오토스케일이라고 불러요
자동으로 할 땐 최대·최소를 정해둬요너무 늘거나 줄지 않게요

오토스케일은 둘 중 하나를 자동으로 결정하는 거예요.자동으로 늘렸다 줄이는 자세한 이야기는 다른 세계에서 이미 다뤄요.

이 건물 투어는 여기까지예요.뼈대(IaaS)부터 자동 배정(쿠버네티스), 저장 방식까지 — 전부 한 건물 안 이야기였어요.

한 줄로

스케일업 = 사무실 하나를 더 크게(수직). 스케일아웃 = 사무실을 더 많이(수평). 오토스케일 = 그 결정을 자동으로 맡기는 것.

스케일업(수직 확장)은 서버 한 대의 성능(CPU·메모리)을 키우는 것, 스케일아웃(수평 확장)은 같은 서버를 여러 대로 늘리는 것이에요. 오토스케일은 지표(트래픽·큐 길이 등)를 보고 이 둘을 최대·최소 한도 안에서 자동으로 수행해요. 자동 확장의 콜드 스타트·스레싱 같은 세부 동작은 SRE 세계의 오토스케일링 페이지에서 더 깊이 다뤄요.

어른들은 이렇게 불러요

스케일업(수직 확장)
Scale-up (vertical)
사무실 하나를 더 크게 만드는 것. 서버 한 대의 성능 자체를 키워요.
스케일아웃(수평 확장)
Scale-out (horizontal)
같은 사무실을 더 많이 빌리는 것. 서버 수 자체를 늘려요.
오토스케일
Auto scale
늘릴지 줄일지를 자동으로 정하는 것. 자세한 동작은 SRE 세계에서 다뤄요. → 줄이 길어지면 직원을 더 부르기
오케스트레이션/쿠버네티스
Orchestration / Kubernetes
몇 자리를 유지할지 정하는 규칙과 그 제품. 실제로 자리를 늘리고 줄이는 걸 실행에 옮기는 역할이에요. → 자동 배정 배지의 그 유명한 제품
가상머신/컨테이너
VM / Container
독채는 스케일업, 칸막이는 스케일아웃에 더 잘 맞아요. 이 건물 투어의 두 번째 페이지였어요. → 독채 사무실과 칸막이 책상
서버리스
Serverless
스케일 결정 자체를 신경 쓸 필요 없는 선택. 이미 극단적으로 자동화된 형태예요. → 시간제 회의실
클라우드 서비스 모델
Cloud service model
뼈대만/인테리어까지/완제품 — 이 건물 투어의 첫 페이지. → 셋 중 골라 빌리기
AI 데이터센터
AI data center
GPU만을 위한 전용 별관. 전용 설비는 대개 스케일업(더 센 장비) 쪽으로 커져요.
