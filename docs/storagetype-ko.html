블록·파일·오브젝트 스토리지가 뭐예요?

블록·파일·오브젝트 스토리지를, 벽돌 자재·폴더 트리·태그 붙은 박스 창고의 차이로 풀어봤어요.

입주사마다 보관하고 싶은 형태가 다 달라요.벽돌, 폴더, 박스 — 다 다른 모양이에요.

한 가지 방식만 있으면 누군가의 짐은 늘 안 맞아요.벽돌도, 박스 태그도 여기선 안 통해요.

블록=벽돌, 파일=폴더 트리, 오브젝트=태그 붙은 박스예요.셋 다 저장하고 꺼내는 방식이 달라요.

블록 = 벽돌 조각가장 날것이고 가장 빨라요
파일 = 폴더 트리사람에게 가장 익숙해요
오브젝트 = 태그 붙은 박스API로 태그를 조회해 찾아요
오브젝트는 거의 무제한으로 쌓여요창고가 끝없이 늘어나요

네 가지 기준에서 성격이 다 갈려요.쓰임새가 뚜렷이 갈려요 — DB엔 블록, 공유문서엔 파일, 사진·백업엔 오브젝트.

오브젝트는 박스 하나를 통째로 바꿔야 해서 느려요.블록은 한 조각만 바꿔도 빨라요.

한 줄로

블록 = 벽돌 조각(가장 빠르고 날것). 파일 = 폴더 트리(사람에게 익숙). 오브젝트 = 태그 붙은 박스(무한 확장, 메타데이터로 조회).

블록 스토리지는 고정 크기 블록 단위로 접근해 DB처럼 빠른 입출력이 필요한 곳에 쓰이고, 파일 스토리지는 디렉터리·파일 계층 구조로 사람이 다루기 쉬워요. 오브젝트 스토리지는 파일을 메타데이터·고유 ID가 붙은 객체로 저장해 API로 조회하며, 수평 확장이 거의 무제한이라 사진·백업·로그 같은 비정형 대용량 데이터에 적합해요. 다만 객체는 일부만 수정하는 덴 비효율적이에요.

어른들은 이렇게 불러요

블록 스토리지
Block storage
벽돌처럼 조각난 저장 단위. 가장 빠르지만 날것 그대로예요.
파일 스토리지
File storage
폴더 트리처럼 정리된 저장 방식. 사람이 다루기 가장 익숙해요.
오브젝트 스토리지
Object storage
태그(메타데이터) 붙은 박스 창고. API로 태그를 조회해 찾아요.
메타데이터
Metadata
박스에 붙이는 태그. 오브젝트를 찾는 열쇠예요.
DAS/NAS/SAN
DAS / NAS / SAN
연결 방식과 나눠쓰는 범위의 차이. 이건 다른 축이에요 — 데이터 모양이 아니라 연결 방식 이야기예요. → 내 서랍, 공용 자료실, 전용 창고망
수평 확장
Horizontal scaling
창고를 옆으로 계속 늘리는 것. 오브젝트 스토리지가 이 방식으로 거의 무제한 늘어나요.
백업
Backup
자료 사본을 따로 하나 더 두는 일. 오브젝트 스토리지가 자주 쓰이는 용도예요.
