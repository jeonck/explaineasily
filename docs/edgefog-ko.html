엣지·포그 컴퓨팅이 뭐예요?

엣지·포그 컴퓨팅을, 멀리 있는 본사 대신 동네 가까운 지점과 그 중간 허브가 먼저 처리해주는 이야기로 풀어봤어요.

동네 끝 방문객은 본사까지 한참 걸려요.거리만큼 기다림도 길어져요.

본사 하나에 다 몰리면 기다림이 늘어요.가까운 곳에서 처리할 방법이 필요해요.

엣지 = 동네 지점, 포그 = 본사와 지점 사이 중간 허브예요.가까운 곳에서 먼저 처리해서 빨라져요.

가까운 곳이 먼저 처리해요엣지 = 동네 지점이에요
포그는 지점 여러 곳을 묶어요본사와 지점 사이 중간 허브예요
거리가 짧을수록 빨라요응답 지연이 줄어요
그래도 결국 본사와 맞춰야 해요동기화가 필요해요

처리 위치에 따라 역할이 나뉘어요.간단한 건 가까이서, 무거운 건 본사가 맡아요.

작은 지점엔 다 담을 수 없어요.결국 본사와 자료를 맞춰야 해요(동기화).

한 줄로

엣지 컴퓨팅 = 동네 가까운 지점에서 바로 처리하기. 포그 컴퓨팅 = 그 지점들을 묶는 중간 허브. 둘 다 본사(중앙)까지 가는 거리를 줄여요.

엣지는 데이터가 생성되는 기기·현장 바로 가까이에서 처리하는 것(예: IoT 센서 바로 옆), 포그는 엣지와 중앙 클라우드 사이에 계층을 하나 더 두어 여러 엣지를 묶어 정리하는 것이에요. 둘 다 지연 시간을 줄이고 중앙 네트워크 부담을 낮추지만, 처리 용량과 저장 범위는 본사(중앙 클라우드)가 더 넓어요.

어른들은 이렇게 불러요

엣지 컴퓨팅
Edge computing
동네 가까운 작은 지점에서 바로 처리. 데이터가 생기는 곳 바로 옆이에요.
포그 컴퓨팅
Fog computing
지점 여러 곳을 묶는 중간 허브. 엣지와 본사 사이 한 계층 더예요.
지연 시간(레이턴시)
Latency
거리만큼 늘어나는 기다림. 가까울수록 짧아져요.
동기화
Synchronization
지점 자료를 본사와 맞추는 일. 지점만으론 전체를 담을 수 없어서 필요해요.
IoT
IoT
현장에서 데이터를 만들어내는 기기. 엣지가 바로 옆에서 처리해주는 대상이에요.
중앙 클라우드(본사)
Central cloud (HQ)
전체 저장·복잡한 분석을 맡는 본사 건물. 이 책 전체의 배경인 그 건물이에요. → 공유 오피스 빌딩
서버리스
Serverless
쓸 때만 여는 시간제 회의실. 엣지에 서버리스 함수를 두기도 해요. → 시간제 회의실
오토스케일
Auto scale
지점 수를 자동으로 늘리는 것. 엣지 지점 수도 수요에 맞춰 늘고 줄 수 있어요. → 사무실을 키울까 더 빌릴까
