명세기반 테스트 설계기법이 뭐예요?

명세기반 테스트 설계기법을, 원고를 다 읽지 않고도 작성 규칙서만 보고 대표 사례를 골라 검사하는 이야기로 풀어봤어요.

모든 경우를 다 검사하려면 평생 걸려요.나이 칸 하나에도 경우의 수가 수천 가지예요.

입력 가짓수는 사실상 무한해요.하나하나 다 넣어보는 건 애초에 불가능해요.

명세기반 테스트설계는 규칙서만 보고 대표 사례를 고르는 거예요.원고를 다 읽지 않고도, 규칙만 보고 적은 수의 대표 사례로 검사해요.

동등분할비슷한 것끼리 묶어 하나만 검사해요
경계값분석기준선 바로 위아래만 봐요
결정테이블규칙 조합을 표로 만들어 검사해요
상태전이테스트이야기 단계가 바뀔 때마다 검사해요

몇 개만 골라도 규칙 위반은 대부분 잡혀요.정상 범위 하나, 범위 밖 둘, 경계선 바로 위아래 — 이 정도면 충분해요.

규칙서만으로 전부를 잡진 못해요.규칙에 없던 드문 조합은 탐색적 테스트 같은 다른 방법과 함께 봐야 해요.

한 줄로

명세기반 테스트 설계기법 = 원고를 전부 읽는 대신, 작성 규칙서만 보고 적은 수의 대표 사례를 골라 검사하는 방법.

명세기반(블랙박스) 테스트 설계기법은 내부 코드를 보지 않고 요구사항 명세만으로 테스트 케이스를 만드는 방법이에요. 대표적으로 비슷한 입력을 묶어 하나만 검사하는 동등분할, 경계선 바로 위아래만 검사하는 경계값분석, 조건 조합을 표로 정리하는 결정테이블테스트, 상태 변화마다 검사하는 상태전이테스트가 있어요.

어른들은 이렇게 불러요

명세기반테스트
Specification-Based Testing
규칙서만 보고 하는 검사. 코드를 안 보고도 할 수 있어요(블랙박스).
동등분할
Equivalence Partitioning
비슷한 입력끼리 묶는 것. 한 그룹에서 하나만 검사해도 충분해요.
경계값분석
Boundary Value Analysis
기준선 바로 위아래만 보는 것. 실수는 경계에서 가장 많이 나요.
결정테이블테스트
Decision Table Testing
조건 조합을 표로 만드는 것. 조건이 여러 개 얽힐 때 빠뜨리지 않게 해줘요.
상태전이테스트
State Transition Testing
이야기 단계가 바뀔 때마다 보는 것. 예약→확정→취소 같은 흐름에 써요.
블랙박스테스트
Black-Box Testing
내부를 안 보고 밖에서만 확인하는 것. 명세기반 기법은 전부 이 범주예요.
테스트케이스
Test Case
고른 대표 사례 하나하나. 입력값과 기대 결과가 한 쌍으로 적혀요.
탐색적 테스트
Exploratory Testing
규칙서에 없는 것까지 사람이 직접 들여다보는 것. 명세기반 기법이 놓친 드문 조합을 보완해요.
