MCP가 뭐예요?

MCP(Model Context Protocol)를 어느 앵무새든 바로 열 수 있는 도구 상자의 공통 규격 이야기로 풀어봤어요.

앵무새마다 도구 상자 모양이 달라요. 같은 도구를 다섯 번 만들어요.환율 도구 하나를 앵무새 다섯 마리에게 주려면, 상자 모양에 맞춰 다섯 번 만들어야 해요. 공방마다도 달라요.

도구 설명, 부탁 쪽지, 결과 모양이 제각각이에요.어떤 공방은 답을 콩 하나로, 어떤 공방은 종이 한 장으로, 어떤 공방은 표로 줘요. 상자마다 새로 맞추다 보면 도구보다 맞추는 일이 더 커져요.

MCP는 도구 상자의 공통 규격이에요. 규격 상자는 어느 앵무새든 바로 열어요.규격대로 만든 상자(서버)에는 도구, 자료, 쪽지 견본이 들어요. 앵무새(클라이언트)는 상자에 뭐가 있는지 묻고, 부탁 쪽지를 규격대로 써요. 상자마다 열쇠(권한)는 따로예요.

상자 하나 만들면 어디서나앵무새마다 새로 안 만들어요
도구·자료·쪽지 견본상자에 세 가지가 들어요
앵무새가 목록을 물어요상자가 같은 모양으로 답해요
상자마다 열쇠 따로허락한 도구만 열려요

앵무새가 목록을 묻고, 상자가 늘 같은 모양으로 답해요. 상자마다 열쇠는 따로예요.상자는 같은 방에 있을 수도(stdio), 멀리 있을 수도(HTTP) 있어요. 어느 쪽이든 묻고 답하는 모양은 같아요. 열쇠가 없는 도구는 목록에 있어도 못 열어요.

규격은 연결만 쉽게 해요. 상자가 안전한지는 말 안 해요.낯선 상자엔 숨은 쪽지가 들어 있을 수 있어요. 열기 전에 누가 만들었는지 보고, 열쇠는 꼭 필요한 도구에만 줘요. 도둑이 만든 도구 이야기는 보안 공급망과 AI 보안에서. 상자를 여러 번 여는 앵무새는 심부름 목록을 스스로 짜는 앵무새에서.

한 줄로

MCP = 도구 상자의 공통 규격. 규격대로 만든 상자(서버)엔 도구·자료·쪽지 견본이 들고, 어느 앵무새(클라이언트)든 목록을 묻고 바로 열어요. 규격은 연결만 쉽게 할 뿐, 낯선 상자가 안전한지는 따로 봐야 해요.

Model Context Protocol. 모델 쪽 앱(클라이언트)과 도구·데이터 제공자(서버)가 도구 목록·호출·결과를 주고받는 공개 규약이에요. 서버는 tools, resources, prompts 를 노출하고, 전송은 stdio(같은 컴퓨터)나 HTTP(원격)예요. 연결 규격일 뿐 서버의 신뢰성은 보장하지 않아서 권한 범위와 출처를 따로 확인해요.

MCP (Model Context Protocol)

MCP 서버 / 클라이언트
MCP server / client
규격 상자 / 여는 앵무새. 서버가 도구를 내놓고, 클라이언트(앵무새 쪽 앱)가 묻고 써요.
도구 · 리소스 · 프롬프트
Tools · resources · prompts
상자 안 세 가지. 돌릴 수 있는 도구, 읽을 수 있는 자료, 미리 쓴 쪽지 견본.
전송
Transport (stdio / HTTP)
같은 방 또는 멀리. stdio 는 같은 컴퓨터, HTTP 는 네트워크 너머. 묻고 답하는 모양은 같아요.
권한
Permissions
상자마다 열쇠. 허락한 도구만 열려요. 꼭 필요한 열쇠만 줘요.
도구 호출
Tool calling
부탁 쪽지. 규격 상자 안 도구도 쪽지로 부탁해요. → 도구 상자
에이전트
Agent
상자를 여러 번 여는 앵무새. 규격 덕에 상자를 갈아 끼우기 쉬워요. → 심부름 목록을 스스로 짜는 앵무새
공급망 위험
