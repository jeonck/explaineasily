In one breath

Paging cuts memory into fixed-size chunks, while segmentation cuts it by logical unit (code, data, and so on) — two different ways of mapping virtual addresses to real memory.

Paging divides both virtual and physical memory into fixed-size chunks (pages/frames) mapped via a page table — simple to implement, with no external fragmentation, though the last partly-filled page wastes space (internal fragmentation). Segmentation divides a program into logically meaningful, variable-sized units (code, data, stack) — making protection and sharing easier, but leaving gaps between segments (external fragmentation). Modern operating systems commonly combine both, paging again inside each segment.

When grown-ups say it

Paging
Cutting into fixed-size chunks. Addresses are based on physical position.
Segmentation
Cutting by logical unit. Divided by role, like code, data, and stack.
Internal Fragmentation
Leftover space wasted inside a fixed-size slot. Common in paging.
External Fragmentation
Unusable gaps left between chunks. Common in segmentation.
Page Table
The table matching virtual slots to real ones. The core structure of paging. → the fake map that makes the whole warehouse mine
Segment Table
The table recording each segment's start and length. Segments vary in size, so length is recorded too.
Segmented Paging
A hybrid that pages again inside each segment. Tries to keep the advantages of both.
Virtual Memory
The broader idea of a fake map that looks roomier than reality. Paging and segmentation are two ways to implement it. → virtual memory and paging
