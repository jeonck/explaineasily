In one breath

TCP guards a registered delivery to the end with three devices: error control (resend what's lost), flow control (match the receiver's pace), and congestion control (slow down when the road jams).

Error control recovers loss and corruption through checksums, ACKs, and retransmission (timeout, fast retransmit). Flow control uses the receive window to throttle the sender so the receiver's buffer never overflows. Congestion control estimates network congestion itself, growing the congestion window via slow start and congestion avoidance, then cutting it on detected loss (AIMD) to keep the whole path from overloading.

When grown-ups say it

Error control
The device that resends what was lost or damaged. Detected via checksum and acknowledgment (ACK).
Flow control
The device that sends only as much as the mailbox can hold. Matches pace to the receive window size.
Congestion control
The device that cuts the count when the road jams. Grows then cuts the congestion window (AIMD).
ACK
The note confirming something arrived safely. Its absence is what triggers a resend.
Timeout/retransmission
The rule that resends when no reply comes in time. A core mechanism of error control.
3-way handshake
The three greetings exchanged before anything is sent. The step TCP takes before any of this control begins. → the registered envelope and the plain one
TCP/UDP
The registered envelope and the plain one. These three devices exist only in the registered envelope (TCP). → the registered envelope and the plain one
5G Network slicing
Splitting one road into dedicated lanes. Lane guarantees shake too once the whole road jams. → splitting the road into lanes
