# Picture Book — 어떤 분야든 그림책 용어집으로

## 결과물

`terms/<분야>/<slug>.py` 한 파일 = 페이지 하나. `python3 build.py` 가 `docs/<slug>-ko.html`, `-en.html`, 목록 `index.html` 을 만든다.
페이지 하나는 **패널 5장(SVG 760px + 한 문장)** + **hero 패널의 요령 카드 4장** + **한 줄 요약** + **용어집 8줄(쉬운 말 → 원어, 다른 페이지 링크)**.
분야 하나는 **세계관 하나**(`terms/<분야>/_WORLD.md`)를 공유한다. 이게 이 방법의 핵심이다 — 용어 100개가 같은 마을에서 일어나야 독자가 그림을 재사용한다.

새 저장소에서 쓰려면 explaineasily 의 `build.py`, `terms/_draw.py`, `.claude/skills/picture-book/` 을 복사하고 `CATEGORIES` 에 분야를 등록한다.

## 절차

### 0. 분야와 세계관

- 기존 분야면 `terms/<분야>/_WORLD.md` 를 읽고 그 안에서 푼다. 없으면 만든다 — [references/world-design.md](references/world-design.md) 의 카드 형식대로 무대·등장인물(모자/옷 색 = 정체)·소품(=개념)·색 규칙·이미 쓴 비유 목록을 한 장에 적는다.
- `build.py` 의 `CATEGORIES` 에 `"폴더": ("한글", "English")` 가 있어야 빌드된다.
- 세계관 조건: 다섯 살이 겪어본 곳 / 역할이 색으로 구분되는 인물 / 소품이 곧 개념 / 지키는 쪽 vs 노리는 쪽 같은 긴장 / 비유가 깨지는 지점이 있음.

### 1. 용어 하나 → 비유 하나

용어가 **하는 일**을 먼저 한 문장으로 쓴다 ("종이 울리기 전에 직접 찾아 나선다"). 그 일을 하는 인물·소품을 세계관에서 고른다. 제목은 용어 이름이 아니라 **비유의 이름**이다 ("종을 기다리지 않는 파수꾼").
이웃 용어와 겹치면 차이를 패널 ①에서 먼저 보여준다 (펜테스트=틈 목록 vs 레드팀=목표 하나·몰래·오래).

### 2. 패널 5장

```
① 문제 상황    무대와 곤란함을 한 장면으로            "종이 안 울려요. 그런데 벽장 속에 누가 있어요."
② 왜 어려운가  잘못하면/그냥 두면 어떻게 되나         "종은 아는 도둑만 울려요."
③ hero        용어 = 비유 한 문장 + 요령 카드 4장     "위협 헌팅은 종을 기다리지 않고 직접 찾아 나서는 거예요."
④ 작동         디테일 한 가지를 크게 (표·비교·타임라인) "질문 하나를 들고 일지를 뒤져요."
⑤ 결과/한계    이어지는 페이지, 비유가 깨지는 곳       "찾은 버릇은 새 종이 돼요."
```
한 패널 = 한 개념 = 한 문장(+부연 두 문장 이내). hero 는 하나. 카드 4장 = 그 용어를 쓰는 요령 (동사구 + 6자 부연).

### 3. 그림

`terms/_draw.py` 의 조각(person, sky/night, castle, bubble, label, icon, dog, corridor, gate …)을 먼저 쓴다. 3페이지 이상 반복되는 새 그림은 `_draw.py` 로 올린다.
- 폭 760 고정, 높이 300~360. 모든 요소 0..760 안. `person(x,y,s)` ≈ 70s×110s.
- 색은 CSS 토큰(`var(--bad)` 등). 고정 크림색 종이(#FFF8E7) 위 글자만 `#142033` 리터럴.
- 그림 속 글자는 `⟦한글|English⟧`. 특수 기호는 ✓ × 만.
- 하단 캡션 y = 높이-20, 그 위 요소 바닥은 25px 이상 위. `night()` 의 달(660,50)을 피한다.
- bubble tail 은 left/right/bottom. Python 문자열 안 같은 따옴표 중첩 금지.

### 4. 파일

같은 분야의 최근 파일을 복사해 시작한다. PAGE 필수 키: `slug, order, title, h1, sub, panels[5], summary, glossary[8]`. 모든 문장은 `(ko, en)` 튜플. `alt` 는 그림 설명(캡션 반복 금지). 관련 페이지는 `small`/`glossary` 에서 `<a href="<slug>-ko.html">` / `-en.html` 로 잇는다. `order` 는 분야 안 연속 번호(사이엔 8.5 같은 소수).

### 5. 검증 → 시각 검수 → 표 → 푸시

```bash
python3 .claude/skills/picture-book/scripts/validate.py --category <분야> --slugs <slug> --strict   # -W error 빌드, SVG XML, 링크, 구조
python3 .claude/skills/picture-book/scripts/render_qa.py /tmp/qa <slug>                            # 패널 5장을 PNG 한 장으로 → Read 로 본다
python3 .claude/skills/picture-book/scripts/update_tables.py --category <분야>                      # README·스킬 표에 행 추가(멱등)
git add -A && git commit -m "Add <Term> (<비유 영문>)" && git push origin main
```
시각 검수에서 보는 것: 겹침, 잘림, 캔버스 밖, 크림 종이 위 밝은 글자, 말풍선이 다른 요소를 덮음. 좌표 몇 개면 직접 고치고 그 패널만 다시 렌더한다.

### 6. 대량 채우기 (10개 이상)

[references/batch-loop.md](references/batch-loop.md). 요약: 분야 표준 용어 목록으로 `coverage_audit.py` → `missing` 을 4개씩 주제별로 묶어 `assets/BRIEF.template.md` 로 브리프 → 에이전트 1개당 4용어 병렬(커밋·표·브라우저 금지, `-W error` 빌드+validate 필수) → 총괄이 `render_qa.py` 로 전 페이지 검수·수정 → validate·update_tables·audit → 푸시 → 목표(예: 90%) 미만이면 반복.

## 문장 규칙

- 첫 캡션만 읽어도 무대가 보인다. 배경 설명으로 시작하지 않는다.
- 주어를 생략하지 않는다 — **누가** 하는지가 이해의 90%.
- 숫자는 감각으로("몇 달", "하루 천 번"); 정확한 수치·원어·약어는 summary 둘째 문단과 glossary 로.
- 말투 "~예요/~해요". 어린이 흉내 금지. 어휘를 낮추지 상대를 낮추지 않는다.
- 쉬워지려고 틀린 말을 하지 않는다. 비유가 깨지는 곳은 숨기지 않고 ⑤에서 말한다.

## 하지 말 것

| 금지 | 이유 |
|---|---|
| 한 분야에 세계관 둘 / 페이지에 비유 둘 | 독자가 어느 그림을 믿을지 모른다 |
| 다른 분야의 세계에 끼워 넣기 | 억지 비유는 틀린 비유가 된다 |
| 그림 없는 패널, 문장 셋 이상 | 글이 그림을 이긴다 |
| 리터럴 색(크림 종이 위 글자 제외) | 다크 모드에서 깨진다 |
| `docs/*.html` 직접 수정 | 생성물이다 |
| 에이전트에게 커밋·표·브라우저 맡기기 | 충돌한다. 총괄이 한 번에 한다 |
